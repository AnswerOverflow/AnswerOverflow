# Discord sign-in 500 fix

## Root cause

`POST /api/auth/sign-in/social` returned HTTP 500 with body `fetch failed`.

`/api/auth/*` is handled by Elysia → `handleAuth` → `convexBetterAuthNextJs().handler.POST(request)`. That library proxies to Convex with Node/undici `fetch`, forwarding the **incoming request body as a stream**.

When a keep-alive socket to `*.convex.site` is stale (peer closed / idle timeout on a warm Vercel instance), undici tries to reuse it. Requests **without** a body (e.g. `GET /get-session`) are transparently retried on a fresh connection. Requests **with a streamed body cannot be replayed**, so the POST dies with `TypeError: fetch failed` before Convex sees anything. Elysia's default error handler then surfaces only `error.message` (`fetch failed`) and drops `error.cause`.

This matches observed behavior: page-load GET session works; human-paced Discord sign-in POSTs fail; rapid curls on fresh connections sometimes succeed. `nxtPslugs` is a Vercel catch-all routing artifact in logged URLs — not the root cause (clean curls without it also 500).

## Fix

In `apps/main-site/src/app/(main-site)/api/handlers/auth.ts`:

1. **`stripNextInternalParams`** — drop `nxtP*` / `nxtI*` query keys before proxying (defensive).
2. **`proxyToConvex`** — buffer the body with `arrayBuffer()`, build a fresh `Request` per attempt, call `handler.GET`/`POST`, **retry once** on `TypeError` / `fetch failed`, log `error.cause`, and return JSON **502** if both attempts fail.
3. **`handleAuth`** GET/POST go through `proxyToConvex` (github callback redirect + anon bot check unchanged).

Buffering stays inside `proxyToConvex` (not `handleAuth`) so Elysia Sucrose does not eagerly parse the body on the route handler.

## Tests

`auth.test.ts` mocks `@convex-dev/better-auth/nextjs` and `botid/server`, covering:

- `nxtPslugs` stripped; other params/headers/body preserved
- retry succeeds after first `fetch failed` with replayable body
- non-network errors propagate (no retry)
- double failure → 502 JSON

`vitest.config.mts` + `"test": "vitest run --no-watch --pool=forks"` added under `apps/main-site`.
